## Поиск без учёта регистра кириллицы

- Причина: SQLite `icontains`/LIKE не выполняет преобразование регистра кириллицы. Простое приведение пользовательского ввода к нижнему регистру не исправляет сравнение с названием в БД.
- Добавлен `restaurants/search.py`: UnicodeSearchFilter сохраняет правила DRF (слова/фразы, экранирование, фильтры, пагинация); для SQLite обе стороны сравнения нормализуются Unicode casefold внутри SQL. SQL-функция регистрируется для каждого соединения через connection_created в AppConfig.ready. В PostgreSQL используется прежний нативный поиск. Миграции и перезапись данных не требуются.
- Общий DRF backend поиска заменён на UnicodeSearchFilter; исправлены также поиск описаний, блюд и категорий. OpenAPI уточняет поведение.
- Проверено: полный backend SQLite 59 cases (57 passed, 2 PostgreSQL-only skips); ESLint и OpenAPI OK; новые desktop/mobile браузерные сценарии 2 passed. PostgreSQL для этого исправления отдельно не запускалась.
